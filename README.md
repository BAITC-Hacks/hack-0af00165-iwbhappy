# Агент-магазин — каркас для HackAlem AI

Агентное торговое приложение: один цикл с tool-calling, три инструмента,
фейковый каталог в SQLite. Агент подбирает товар, сравнивает, оформляет
заказ и принимает возврат. Справа видно, что он реально делает.

Каркас собран до хакатона намеренно «скучным»: в день Х правится
каталог, промпт и, если нужно, один инструмент — остальное не трогается.

---

## Запуск

```bash
npm install
npm run dev
```

Открыть http://localhost:3000. Ключ не нужен — без него приложение
работает в записанном режиме и проходит весь сценарий.

С живой моделью:

```bash
cp .env.example .env.local   # вписать OPENAI_API_KEY
npm run dev
```

Прогнать весь сценарий без браузера (10 секунд, запускать после каждой правки инструментов):

```bash
npm run smoke
```

## Структура

```
data/products.json          каталог — здесь меняется предметная область
src/lib/config.ts           модель, ключ, таймауты, лимиты — всё в одном месте
src/lib/db.ts               SQLite: схема, засев, поиск, корзина, заказы
src/lib/logger.ts           лог вызовов + кольцевой буфер для /api/state
src/lib/llm/types.ts        типы, независимые от провайдера
src/lib/llm/client.ts       стриминг, таймауты, ретраи, запасная модель, откат в mock
src/lib/llm/mock.ts         записанные ответы: демо работает без сети
src/lib/agent/tools.ts      три инструмента: JSON Schema + zod-валидация + исполнение
src/lib/agent/prompts.ts    системный промпт и демо-кнопки
src/lib/agent/loop.ts       агентный цикл, отдаёт поток событий
src/lib/agent/bridge.ts     мост «синхронный колбэк -> асинхронный генератор»
src/app/api/chat/route.ts   цикл наружу через SSE
src/app/api/state/route.ts  корзина, заказы, режим, последние логи
src/app/api/reset/route.ts  сброс демо между прогонами
src/components/AgentApp.tsx весь интерфейс
scripts/smoke.ts            сквозной прогон сценария
```

## Три инструмента

| Инструмент | Что делает | Покрывает |
|---|---|---|
| `search_catalog` | поиск с фильтрами и ранжированием | подбор, сравнение |
| `update_cart` | add / remove / set_qty / clear / view | корзина |
| `manage_order` | place / list / status / return | оформление, возврат |

Больше инструментов на пятичасовом хакатоне добавлять не стоит: каждый
новый инструмент — это лишняя ветка, которую придётся чинить в последний час.

---

## Что уже защищено

- **Нет сети или ключа** — `LLM_MODE=auto` уводит в записанный режим, сценарий
  доходит до конца. В шапке загорается `MOCK`, чтобы это не выглядело обманом.
- **Rate limit / 5xx / таймаут** — до 3 попыток с экспоненциальной паузой,
  затем переход на `LLM_FALLBACK_MODEL`, затем mock.
- **Модель прислала мусор в аргументах** — zod отклоняет, текст ошибки уходит
  обратно модели, даётся одна попытка переписать вызов.
- **Инструмент упал** — цикл не рушится, модель получает ошибку словами.
- **Пустая выдача поиска** — фильтры сохраняются, текстовое условие снимается.
- **Длинный диалог** — история обрезается только по границе реплики
  пользователя, чтобы не осиротить tool-ответы и не поймать 400.

## Деплой на Vercel

```bash
npx vercel --prod
```

### База данных

SQLite на Vercel живёт в `/tmp`, и он свой у каждого инстанса: между двумя
соседними запросами вас может раскинуть по разным лямбдам и корзина
пропадёт посреди демо. Приложение это переживёт и honest-badge `БД в /tmp`
покажет, но на защите так лучше не рисковать.

Пять минут на Turso убирают риск полностью — диалект тот же, код не меняется:

```bash
npm i -g @tursodatabase/turso-cli   # или brew install tursodatabase/tap/turso
turso auth signup
turso db create hackalem
turso db show hackalem --url        # -> libsql://hackalem-<org>.turso.io
turso db tokens create hackalem     # -> токен
```

В Vercel → Settings → Environment Variables:

| Переменная | Значение |
|---|---|
| `DB_URL` | `libsql://hackalem-<org>.turso.io` |
| `DB_AUTH_TOKEN` | токен из команды выше |
| `OPENAI_API_KEY` | ключ |
| `LLM_MODE` | `auto` |
| `LLM_MODEL` | `gpt-4.1-mini` |

### Запасной вариант — туннель с ноутбука

Если Vercel отвалился или организаторы дали неудобную сеть:

```bash
npm run dev
npx cloudflared tunnel --url http://localhost:3000
```

Публичная ссылка появится в выводе. Держать этот вариант проверенным
**до** выхода к жюри, а не вместо.

## Сценарий демо

Четыре кнопки под полем ввода проходят весь путь:

1. «Нужен лёгкий ноутбук для учёбы до 500 000 ₸» → `search_catalog`
2. «Сравни с вариантом подешевле и посоветуй один» → `search_catalog` с сохранённой категорией
3. «Бери его и оформляй заказ» → `update_cart` + `manage_order` **в одном ходу**
4. «Ноутбук не подошёл, оформи возврат» → `manage_order(return)`

Шаг 3 — главный: два инструмента за одну реплику, это и есть agentic.
Кнопка «Сброс демо» возвращает всё в исходное между прогонами.

## Грабли

- **Не запускать `npm run build`, пока работает `npm run dev`.** Прод-сборка
  перетирает `.next` под работающим дев-сервером, и он начинает сыпать
  `Cannot find module './873.js'` на каждый запрос. Лечится так:
  остановить dev, `rm -rf .next`, запустить заново. В день Х это случится
  ровно в тот момент, когда вы решите «проверю, что собирается, перед деплоем».
- Локально на Windows Next может не загрузить нативный SWC и уехать на WASM —
  сборка идёт, но медленнее. На Vercel этого не происходит.
- История диалога живёт на клиенте. Перезагрузка страницы очищает переписку,
  но корзина и заказы остаются — они в базе.
