# Защита перед жюри

Шпаргалка на случай, если готовить её будет некогда. Читать не с листа —
это опорные точки, а не текст.

---

## Питч, полторы минуты

> На сайте ekt.kz — каталог электротехники на десятки тысяч позиций.
> Клиент пишет в чат «нужен автомат на 16 ампер» и ждёт менеджера.
>
> Мы сделали агента, который отвечает по каталогу сам: наличие,
> характеристики, сертификат, аналог, условия покупки — и собирает
> корзину.
>
> Три вещи, которые отличают это от обёртки над моделью.
>
> **Первое. Каталог настоящий.** Мы выгрузили его из боевого API
> «Электрокомплекта»: реальные артикулы, цены, остатки по двадцати
> четырём складам и собственные связи рекомендуемых товаров. Условия
> доставки и оплаты — с их же сайта. Выдуманы только сертификаты: их
> в API нет, и они помечены как демонстрационные прямо в интерфейсе.
>
> **Второе. Корзина не меняется без согласия клиента — и это проверяет
> сервер, а не промпт.** Агент может только предложить. Подтверждение
> идёт мимо модели. Модель физически не способна добавить товар сама.
>
> **Третье. Данные честные.** В боевой выгрузке остаток лежит в том
> числе на складах «Брак» и «Витрина», а описание товара противоречит
> его же характеристикам. Мы это нашли и обработали: брак не считается
> наличием, числа берутся только из характеристик.
>
> Работает без интернета в записанном режиме — на площадке с Wi-Fi
> на две с половиной тысячи человек это не паранойя.

## Вопросы, которые зададут

**«А если модель решит добавить товар сама?»**
Не сможет. Добавление — отдельный инструмент, который сервер исполняет
только при двух условиях: предложение создано в предыдущем ходу и
последняя реплика клиента прошла проверку на согласие. Текст реплики
сервер берёт сам, до обращения к модели. Кнопка «Да» вообще идёт мимо
модели. Покажу: пишу «добавь два автомата» — корзина пуста, появилась
карточка. Отвечаю «нет» — корзина по-прежнему пуста.

**«Почему не просто запрет в промпте?»**
Промпт — это просьба. Жюри спросит ровно это, и ответ «мы написали
модели не делать так» разваливается от первого джейлбрейка. У нас
инвариант в коде и одноразовость на уровне базы.

**«Откуда данные?»**
API партнёра, `/api/products` и `/api/products/detail`. Выгрузка
однократная, в репозитории лежит срез на 300 позиций. В рантайме сеть
к ekt.kz не нужна — демо не зависит от чужого сервера.

**«Что синтетическое?»**
Только сертификаты — их в API нет. Помечены как демонстрационные и
в README, и в интерфейсе. Условия покупки взяты с публичных страниц
ekt.kz, источник и дата сверки записаны в файле.

**«Казахский язык?»**
Есть. Язык ответа определяет сервер по буквам, которых нет в русском
алфавите: правило в промпте модель игнорировала, мы это поймали живым
прогоном — ноль казахских ответов из шести. После переноса решения
на сервер — шесть из шести. Подтверждение тоже понимает казахский:
«иә, қосыңыз» добавляет, «қосуға бола ма» — нет, это вопрос.

**«Когда агент зовёт человека?»**
Крупная партия, претензия, доставка не по Алматы, прямая просьба.
Даёт реальные телефоны и часы работы и не обещает обратного звонка —
этого мы гарантировать не можем.

**«Что с галлюцинациями по цене и наличию?»**
Числа модель не придумывает: они приходят из инструментов. В боевых
данных нашлась позиция, где в описании «160А», а в характеристиках
«250 А» — поэтому источником объявлены только характеристики,
а описание показывается как текст.

**«Как это встроится в наш сайт?»**
Одна строка `<script>`. Показать вживую: hackalem10.vercel.app/demo-site —
чужая витрина с другим оформлением, виджет в углу. Iframe и shadow DOM
изолируют стили, `postMessage` проверяет origin с обеих сторон, и по
нему не ходит ничего, кроме служебных сообщений. Платформа сайта не
имеет значения.

**«Почему Excel разбирается своим кодом, а не библиотекой?»**
Потому что разбирается файл, который прислал кто угодно, а у готового
пакета известные уязвимости. Формат — zip с XML внутри, это читается
средствами Node. Ноль новых зависимостей, ничего из файла не
исполняется.

**«Как использовали Codex?»**
Постановки задач лежат в репозитории, в `docs/codex/`. Разделение
ролей описано в `AGENTS.md`: контракты инструментов, правила поведения
и приёмочные критерии — одна зона, реализация — другая.

**«Что не успели?»**
Сопутствующие товары как отдельный сценарий: сейчас партнёрские
рекомендации идут только в аналоги. Приоритет был отдан правилу
подтверждения и достоверности данных.

## Порядок показа

Тот же, что в приёмочных тестах — жюри, вероятнее всего, спросит
именно так.

1. Запрос по существующему артикулу → характеристики, наличие,
   сертификат.
2. Позиция с нулевым остатком → аналог с обоснованием.
3. Вопрос об условиях покупки.
4. **Просьба добавить без «да» → корзина пуста.** Затем «да» →
   позиция появилась. Это главный пункт, на нём не торопиться.
5. Ссылка на корзину.

Если спросят про вложения — загрузить спецификацию: карточка на
несколько позиций, блок «не нашли в каталоге», и корзина меняется
только после подтверждения.
