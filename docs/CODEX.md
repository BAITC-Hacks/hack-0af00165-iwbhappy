# Как гонять Codex по этому репозиторию

Правила использования Codex на хакатоне обязательны, но это не значит
«отдать всё Codex». Пять часов — слишком мало, чтобы разгребать за
агентом архитектурный бардак. Ниже — разделение, которое реально работает.

---

## Настройка (сделать до хакатона, 10 минут)

```bash
npm i -g @openai/codex
codex login
```

Проверить, что Codex видит правила репозитория:

```bash
cd C:/PROJECTS/hackalem
codex
```

В первом же ответе он должен сослаться на `AGENTS.md` (три инструмента,
`npm run smoke`). Если не сослался — скажи прямо: «прочитай AGENTS.md
и перескажи ограничения». Дальше не начинай, пока он их не назовёт.

Режим одобрений: рабочий каталог на запись, команды — с подтверждением.
Codex должен уметь сам запускать `npm run smoke`, иначе половина
ценности теряется: он не увидит, что сломал.

**Заведи git до первой задачи.** Без него откат правки Codex превращается
в археологию:

```bash
git init && git add -A && git commit -m "каркас до хакатона"
```

---

## Главное правило

> Codex получает задачу, у которой есть **команда проверки**.
> Нет команды проверки — задача твоя, не его.

`npm run smoke` и `npx tsc --noEmit` — это и есть проверка почти для всего
бэкенда. Для интерфейса проверки нет, поэтому интерфейс правь сам или
проверяй глазами сразу же.

---

## Что отдавать Codex

Хорошо получается — механическое, локальное, проверяемое:

- **Расширение каталога.** «Добавь в `data/products.json` 12 товаров
  в категории X с теми же полями. Проверь `npm run smoke`.»
- **Новое действие в существующем инструменте.** «Добавь в `manage_order`
  действие `cancel`: отменяет заказ в статусе `placed`. Добавь в zod-схему,
  в JSON Schema, в `db.ts` функцию, в `mock.ts` ветку. `npm run smoke`.»
- **Обработка краевых случаев.** «Что будет, если модель пришлёт
  `qty: 999`? Найди и закрой дыры в `tools.ts`.»
- **Тексты ошибок.** «Перепиши сообщения об ошибках инструментов так,
  чтобы модель могла по ним сама починиться.»
- **Косметика интерфейса по точному описанию.** «В `AgentApp.tsx` в карточке
  заказа покажи дату. Формат `21 сен, 14:30`. Остальное не трогай.»
- **Наполнение под кейс.** В день Х это основное: переписать каталог,
  категории и демо-фразы под формулировку трека.

## Что делать самому

- **Системный промпт** (`prompts.ts`). Codex пишет обтекаемо; промпт — это
  твоё представление о демо, его нельзя делегировать.
- **Сценарий демо и четыре кнопки.** Это питч, а не код.
- **Всё в `loop.ts` и `bridge.ts`.** Управляющий поток и стриминг —
  место, где ошибка выглядит как работающий код. Я там уже поймал
  две штуки, которые типы не ловят.
- **Решение «добавляем фичу или нет».** Codex никогда не скажет «не надо».
- **Последний час.** После T+4:15 Codex не трогает код вообще.

## Как формулировать

Плохо:

> улучши поиск

Хорошо:

> В `src/lib/db.ts`, функция `searchProducts`. Сейчас при `sort_by: "rating"`
> товары без отзывов попадают наверх. Отсортируй по `rating DESC, reviews DESC`,
> но товары с `reviews < 50` опускай ниже остальных.
> Не трогай `tokenize` и запасной запрос без текстового условия.
> Проверь: `npm run smoke` должен остаться зелёным.

Рабочий шаблон — четыре строки:

```
Файл и функция: <где>
Сейчас: <что происходит>
Нужно: <что должно происходить>
Не трогай: <границы>
Проверка: npm run smoke && npx tsc --noEmit
```

«Не трогай» — самая важная строка. Без неё Codex делает рефакторинг
заодно, и ты теряешь двадцать минут на разбор диффа.

## Ритм работы

Одна задача — одна ветка — один дифф — один просмотр.

```bash
git checkout -b fix-search
codex exec "…задача по шаблону…"
git diff                    # читать глазами, всегда
npm run smoke
git checkout main && git merge fix-search   # или git checkout . и забыть
```

Не давай Codex две задачи подряд без просмотра диффа между ними.
Второй дифф ляжет на непроверенный первый, и разбирать придётся оба.

**Параллельность.** Пока Codex делает каталог, ты правишь промпт.
Пока Codex закрывает краевые случаи, ты репетируешь питч. Не сиди
над его выводом — это самая дорогая ошибка на хакатоне.

---

## Когда останавливать

Останови и делай сам, если:

- дифф больше ~80 строк на задачу, которая звучала как мелкая;
- Codex второй раз подряд не может сделать `npm run smoke` зелёным;
- он предлагает добавить зависимость;
- он начал «заодно» править файл, которого не было в задаче.

Откат стоит одну команду:

```bash
git checkout .
```

Сделай это без сожалений. Спорить с агентом дороже, чем переписать самому.

---

## Для защиты

Условие «обязательно использовать Codex» жюри почти наверняка проверит
вопросом. Держи наготове конкретику, а не «мы использовали Codex»:

- один-два скриншота сессии с понятной задачей и диффом;
- честный ответ, что отдавал агенту, а что делал сам, и **почему** —
  «управляющий поток агентного цикла я писал руками, потому что там
  ошибка выглядит как рабочий код» звучит куда сильнее, чем «всё написал Codex»;
- если Codex что-то сломал и ты откатил — расскажи и это. Жюри
  оценивает инженерную зрелость, а не лояльность инструменту.
