Правка к задаче 01. Мелкая, но она чинит главный козырь решения.

ФАЙЛ: scripts/seed-from-api.ts, затем перевыгрузка data/catalog.json.

СЕЙЧАС

В каждой записи каталога нет поля `id` — числового идентификатора товара
в API ekt.kz. При этом поле `alternatives` заполняется из
`properties.RECOMMEND`, а там лежат именно эти самые `id` (числа вроде 22493).

Итог: из 365 ссылок в alternatives не резолвится НИ ОДНА, потому что искать
их не по чему. Рекомендации, которые партнёр проставил сам, сейчас не
работают, и подбор аналогов держится только на запасном алгоритме.

Это же отсутствие `id` уронило засев базы: в схеме он был первичным ключом,
все товары получали 0 и затирали друг друга, в SQLite доезжал один товар из
трёхсот. Схему я уже починил — ключ теперь `sku`. Но `id` всё равно нужен,
чтобы заработали аналоги от партнёра.

НУЖНО

1. Добавить в каждую запись каталога поле `id` — число, как в API
   (`items[].id` и `detail.id`). Именно число, не строка.

2. Проверить, что `alternatives` остаются массивом тех же идентификаторов,
   что и `id` других товаров. Если удобнее хранить их строками — храни
   строками, но тогда и `id` пиши так же: сравнение идёт по совпадению.

3. Перевыгрузить каталог.

4. Добавить в scripts/check-catalog.ts ещё две проверки:
   - у каждого товара есть непустой `id`;
   - хотя бы у 15 товаров минимум одна ссылка из `alternatives` указывает
     на товар, который ЕСТЬ в этом же файле. Печатать фактическое число.

   Вторая проверка — суть задачи. Если она не выполняется, значит срез
   каталога слишком разрежен: рекомендации ведут на товары за его
   пределами. Тогда увеличь глубину обхода страниц, чтобы срез стал
   плотнее, и перевыгрузи. Руками ничего не дописывай.

3а. Чистка названий не доведена до конца.

У товара с артикулом 404029х название сейчас такое:

    11204 ВА 63 (1ф) 20А 404029 Legrand (10) !!!

Префикс `***` чистильщик снимает, а хвостовой `!!!` остаётся. Сними
и его, и любые другие висящие маркеры в конце названия (`!!!`, `***`,
повторяющиеся восклицательные знаки, лишние пробелы). Оригинал
по-прежнему сохраняется в rawName.

ЗАОДНО, если останется время

`data/terms.json` сейчас отвечает слишком обтекаемо: «доставка согласуется
с менеджером» — это не содержательный ответ, а третий приёмочный тест
требует именно содержательный. Допиши конкретику по оплате, доставке,
минимальной партии и самовывозу: сроки, города, способы оплаты. Данные
синтетические, это разрешено разделом 4 — но они должны быть осмысленными.
Формат файла можно оставить плоский, читатель понимает оба.

НЕ ТРОГАЙ: src/ целиком, scripts/smoke.ts.

ПРОВЕРКА — все четыре команды:
  npm run seed
  npm run check
  npm run smoke
  npm run demo

и сценарий защиты должен пройти на новом каталоге целиком.
