## 1. `src/lib/llm/mock.ts` — маршрутизация по намерению (ГЛАВНОЕ)

Записанный режим — это наше демо, если на площадке ляжет Wi-Fi
(AGENTS.md §7). Сейчас он держит только пять фраз сценария. Проверка
Claude — реальный вывод mock на свободные реплики:

```
> добавь УПп 60/40.1.1 со стыковочными узлами и винтами
  [propose_add: нет такого артикула: 60/40.1.1]      ← «60/40.1.1» принят за артикул
> найди автоматический выключатель на 16А
  [get_product] Клемма соед. 2-пров. WAGO …           ← залип на прошлом товаре
> есть УЗО?                  → та же клемма
> как связаться с менеджером? → та же клемма
> иә, қосыңыз                 → та же клемма
```

Причины: `skuFromHistory` подтягивает товар из прошлых ходов, когда
в реплике его нет; `AFFIRM` на строке 126 использует `\b` с кириллицей
(AGENTS.md §13 — не работает); нет веток «менеджер», «поиск по
названию», казахского.

### Как должно быть

Каждый ход решается по ТЕКУЩЕЙ реплике клиента. История используется
только в двух случаях: найти висящее предложение (для «да»/«нет») и
понять, что клиент отвечает на вопрос «подтверждаете?».

Порядок проверок в `mockTurn` (первое совпадение выигрывает):

1. **Согласие** — `isAffirmative(text)` из `../agent/tools` (не своя
   регулярка!) и есть висящее предложение → `confirm_add`.
2. **Отказ** — есть висящее предложение, а в реплике «нет / не надо /
   отмена / жоқ / керек емес» → без инструментов: «Хорошо, не добавляю.»
3. **Условия** — оплат, доставк, самовывоз, гарант, возврат, партия,
   минимальн, төлем, жеткізу → `get_terms` с нужной темой (payment,
   delivery, pickup, warranty, returns, min_order; несколько тем → all).
4. **Менеджер** — менеджер, человек, оператор, позвонить, претензи,
   жалоб, менеджермен → `get_terms({topic: "contacts"})`.
5. **Добавить**: добав, в корзину, положи, куплю, беру, закаж, қос,
   себетке.
   - артикул есть в реплике → `propose_add(sku, qty)`;
   - артикула нет → `search_catalog(текст без глагола)`; на следующем
     шаге, если нашлось, → `propose_add` по первой позиции и в ответе
     назвать, что именно предложено. Это безопасно: предложение ничего
     не меняет, подтверждение всё равно нужно.
6. **Артикул в реплике** без глагола добавления → `get_product`; если
   `available` = 0 → `find_alternatives`.
7. **Аналоги** — аналог, замен, взамен, вместо → `find_alternatives`
   по артикулу из реплики, иначе из последнего `get_product` в истории.
   Это единственное место, где разрешено брать товар из истории.
8. **Всё остальное** → `search_catalog(текст)`, показать до 5 позиций
   с артикулом, ценой и наличием, спросить, какой интересует.

### Что считать артикулом

Токен от 5 символов, в котором есть цифра И который находится в
каталоге. Проверяй существование: `await getProduct(token)` из
`../db`, и только найденный считай артикулом. «60/40.1.1» в каталоге
нет — значит это часть названия, и идёт ветка поиска. Делай `mockTurn`
async: вызов в `client.ts` уже `await mockTurn(messages)`, его трогать
не нужно.

### Язык

`detectLang` из `../agent/loop`. Для казахского — казахские шаблоны
для служебных фраз (вопрос подтверждения, «добавлено», «не нашёл»,
«не добавляю»). Данные из инструментов (названия, условия) остаются
как есть.

## 2. Сопутствующие после кнопки «Да»

`POST /api/confirm` теперь возвращает `related: [{sku, name, price, reason}]`
(до двух). После успешного подтверждения кнопкой покажи их в ленте
под сообщением о добавлении: строка «К этому товару рекомендуют:»
(kk: «Бұл тауарға ұсынылады:») и до двух кнопок-подсказок с названием
и ценой, под ними мелко `reason`.

Нажатие отправляет в чат ОБЫЧНУЮ реплику «Добавь <sku> в корзину,
1 штуку» (kk: «<sku> себетке қосыңыз, 1 дана»). Корзину напрямую не
трогать — агент сделает предложение, клиент подтвердит. Это правило
раздела 6, не нарушать.

## 3. Страница `/try` — показать виджет на настоящем ekt.kz

Партнёр должен увидеть ассистента на СВОЁМ сайте, а доступа к сайту
у нас нет. Закладка в браузере подгружает виджет в открытую страницу
ekt.kz — только у того, кто нажал, сайт при этом не меняется.

`src/app/try/page.tsx` — простая страница:
- заголовок «Ассистент на вашем сайте»;
- ссылка-закладка, которую перетаскивают на панель закладок:
  `javascript:(()=>{if(document.querySelector('[data-ekt-assistant-widget]'))return;const s=document.createElement('script');s.src='<ORIGIN>/embed.js';document.body.appendChild(s);})()`
  где `<ORIGIN>` — адрес текущего сайта (`window.location.origin` на
  клиенте или из заголовков запроса);
- три шага: «Перетащите кнопку на панель закладок → откройте ekt.kz →
  нажмите закладку»;
- строка мелко: «Сайт ekt.kz не изменяется: виджет появляется только
  в вашем браузере»;
- для сравнения — однострочник, который партнёр вставил бы в шаблон
  Bitrix: `<script src="<ORIGIN>/embed.js" async></script>`.

Проверять на ekt.kz не нужно — у тебя нет браузера. Claude проверит.
