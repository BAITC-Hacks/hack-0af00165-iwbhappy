## 3. Инварианты — не ломать ни при каком рефакторинге

Это то, что защищается перед жюри. Каждый пункт проверяется смоуком;
если проверка начала мешать — неправ код, а не проверка.

1. **Корзину меняет ровно одно место** — `consumeProposal` в
   `src/lib/db.ts`. Второго пути изменения корзины в приложении нет,
   и появляться он не должен. Спецификация из файла намеренно
   проведена через ту же функцию.
2. **Агент не вызывает `confirm_add` по своей воле.** Сервер исполнит
   вызов, только если сырая последняя реплика клиента прошла матчер
   согласия. Текст реплики сервер сохраняет сам, до обращения к модели.
3. **Предложение создано в предыдущем ходу.** Иначе модель в одном
   ответе вызовет `propose_add` и сразу `confirm_add`, подставив под
   проверку ту же фразу клиента. Заслон — `turnStartedAt`.
4. **Одно предложение срабатывает один раз** — условный
   `UPDATE ... WHERE status='pending'`, а не чтение с последующей
   записью. Гонкой двух запросов не обойти.
5. **Числа только из инструментов.** Источник характеристик —
   `specs` (то есть `properties` из API), цена и пересчитанный остаток.
   `description` показывается как текст и никогда не служит источником
   чисел: в боевых данных они противоречат друг другу (AGENTS.md §12.2).
6. **Служебные склады не считаются наличием.** Брак, витрина,
   перемещение, образцы — отфильтрованы. `quantity` верхнего уровня
   API игнорируется, остаток пересчитывается сам.
7. **Сертификаты помечены как демонстрационные.** Их нет в API,
   они синтезированы. Выдавать придуманный сертификат за настоящий —
   ровно тот недостоверный ответ, который запрещён разделом 11.
8. **Заказ не оформляется, платёжные данные не запрашиваются.**
   Финальный шаг — ссылка на корзину.

## 4. Границы, которые стоили времени

Полный список — AGENTS.md §13. Три самых дорогих:

- `\b` в регулярках не работает с кириллицей. Матчер согласия разбирает
  текст на слова намеренно — не переписывать на границы слов.
- Регулярка из шаблонной строки теряет `\d`. Только литералы.
- Проверки с русским текстом запускать файлом через `tsx`, не через
  `node -e`: консоль на этой машине калечит кириллицу и тест соврёт.

И ещё одно, чего в §13 нет: **`npm run build` при работающем `npm run dev`
ломает дев-сервер.** Перед сборкой остановить dev.

## 5. Команды

```bash
npm run dev        # разработка
npm run typecheck  # ноль ошибок — обязательное условие
npm run smoke      # 63 проверки, без модели, быстро
npm run demo       # поведение через агентный цикл; -- --live живая модель, -- --live --kk казахский
npm run seed       # перевыгрузка каталога из API партнёра (нужен .env.local)
npm run check      # валидация data/catalog.json
npm run build      # прод-сборка; сначала остановить dev
```

Коммит — не реже раза в час, это требование хакатона. Ветка `main`
должна повторять рабочую ветку: сдаётся `main`.

## 6. Если что-то сломалось за полчаса до защиты

1. `git log --oneline` — найти последний коммит, где смоук был зелёный.
2. `git checkout <sha> -- <сломанный файл>` — точечно, не всё дерево.
3. Если не помогло — `LLM_MODE=mock` и показывать записанный сценарий.
   Он проходит целиком без сети. В шапке загорается `MOCK`; выдавать
   записанный ответ за живую модель нельзя, но показать продукт можно.
4. Если не поднимается и это — демо с ноутбука через туннель.

Порядок именно такой: сначала сузить область, потом снижать амбиции.
