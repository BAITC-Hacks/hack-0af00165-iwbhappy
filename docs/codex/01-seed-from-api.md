Задача P0 №2 из раздела 10 AGENTS.md: выгрузка каталога из API партнёра.

Сначала прочитай AGENTS.md целиком. Разделы 4 и 12 переписаны только что и
содержат полную таблицу соответствия полей и правила фильтрации. Они —
источник истины, отступать от них нельзя.

ФАЙЛЫ: scripts/seed-from-api.ts (новый), scripts/check-catalog.ts (новый),
data/terms.json (новый). data/catalog.json — перезаписывается.

СЕЙЧАС: data/catalog.json содержит каталог ноутбуков от прошлого прототипа,
к кейсу отношения не имеет. API партнёра не используется вообще.

НУЖНО

1. scripts/seed-from-api.ts — один прогон, пишет data/catalog.json.
   - Доступы читает из .env.local собственным мини-парсером: EKT_API_BASE,
     EKT_API_USER, EKT_API_PASSWORD. Новых зависимостей не ставить, dotenv
     не добавлять.
   - basicAuth заголовком: Authorization: Basic base64(user:password).
   - Обходит GET {base}/products?page=N с page=1. На каждый товар из items[]
     делает GET {base}/products/detail?id=ID — характеристики и склады есть
     только там.
   - Пауза 120 мс между detail-запросами. Партнёрский сервер не долбить.
   - Прогресс в консоль: номер страницы, собрано, пропущено.
   - Стоп при 300 собранных товарах, либо при пустом items[], либо на 60-й
     странице — что наступит раньше.
   - Маппинг полей строго по таблице раздела 4.
   - Фильтрация складов и пересчёт остатка строго по разделу 12.1. Поле
     quantity верхнего уровня игнорировать полностью.
   - Чистка name и sku по разделу 12.3, оригинал сохранять в rawName.
   - certificate синтезировать детерминированно по sku, примерно трети
     позиций, внутри объекта обязательно поле "demo": true.
   - На сетевой ошибке и 5xx — 2 ретрая с паузой. Товар, который не удалось
     получить, пропускается со счётчиком; весь прогон из-за одного товара
     не падает.

2. data/terms.json — условия покупки: оплата, доставка, минимальная партия,
   самовывоз (раздел 4). Структура на твоё усмотрение, но плоская и удобная
   для будущего инструмента get_terms.

3. scripts/check-catalog.ts — валидатор. Печатает по каждому пункту
   «пройдено/нет» и фактическое число, выходит с кодом 1 при любом провале:
   - товаров не меньше 250
   - не меньше 5 позиций со статусом out_of_stock
   - не меньше 5 позиций с суммарным доступным остатком от 1 до 3
   - не меньше 10 позиций с непустым alternatives
   - не меньше 30 позиций с непустым certificate
   - у каждого товара непустые sku, name, category и price больше нуля
   - ни в одном stock нет склада, чьё имя попадает под чёрный список 12.1

НЕ ТРОГАЙ: каталог src/ целиком, package.json, next.config.ts, tsconfig.json,
.env.local, существующий scripts/smoke.ts. Рефакторинг «заодно» не делать.

ПРОВЕРКА — обе команды обязаны пройти, о готовности не сообщать раньше:
  npx tsx scripts/seed-from-api.ts
  npx tsx scripts/check-catalog.ts

Если валидатор падает из-за нехватки позиций нужного типа — увеличь глубину
обхода страниц в seed-from-api.ts и перезапусти выгрузку. Руками в
catalog.json ничего не дописывать: данные должны быть из API.
